## D. 边界条件

### D1 ⚠️ 脆弱代码（非 bug）—— 依赖隐式不变量

`lib/server/activity_feed.dart:236-240`

```dart
// 等你确认：放在最上面（时间线是新的在上）
for (final p in pending) {
  items.add(ActivityItem(...));        // 226-234：把每个 pending 都 append 到 items 末尾
}

ActivityItem? current;

  current = items.last;                // 239 ← 取「刚 push 的那条」

```

**判断依据不是 `pending`**（那是另一个集合），而是「226-234 行把 pending 元素都 append 到了 items 末尾」这个**隐式不变量**。

**当前安全**（`pending.isNotEmpty` → 循环至少跑一次 → `items` 必非空），但**脆弱**：将来谁把那个循环改成 `insert(0, …)`，或把循环挪到 239 行之后，这里立刻 `Bad state: No element`。

**建议**：在循环里直接把 item 记下来，不依赖「最后一条就是它」。

### D2 ⚠️ 类型断言风险

`lib/server/session_cache.dart:232`

```dart

    ? null
    : CachedMessage.fromJson(
```

### E1 为什么不是「补个参数就完事」

E1 的根因是**同一功能两份实现**（表单从 `conn_page` 抽成 `conn_edit_page` 时漏带了 timeout）。
只在新页面补上 8 秒，两处依旧是两个独立的字面量，以后改一处漏一处就又会走偏。
所以把值抽成 `kConnectTestTimeout` 单点定义，两个调用方共享 —— **从设计上消除复发可能**。
