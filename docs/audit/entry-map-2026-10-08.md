## 三、多入口功能：逐个判断

扫描方法：① 查每个「页面级组件」被构造的次数；② 查每个「打开某功能」的函数被调用的位置；
③ 用中文文案反查 i18n key 的全部使用点。

**结果：全 App 真正有多个入口的页面级功能只有 1 个（「文件浏览」）；另有 1 个虽然不是多入口、但入口藏得太深（「AI 配置」），一并处理。**

| 功能 | 入口 | 决定 |
|---|---|---|
| **`WorkspaceFilesPage`（文件浏览）** | ① `chat_page.dart:2481`「浏览工作区文件」（在「本轮改动」面板里）<br>② `settings_page.dart:273`「文件浏览」（工作区分组里）| **保留两个** ✓ 上下文不同：① 是「看这次会话改了什么」的延伸，② 是「管理文件」的通用入口。且**两处文案本来就不同**，用户能分辨。|
| **`ConfigPage`（AI 配置）** | 只有 1 个：`settings_page.dart:223` | **不是多入口，而是藏得太深** → 见第四节 |

### 被误判为多入口、实际不是的（澄清）

| 扫描信号 | 实际情况 |
|---|---|
| 「目标」出现在多个文件（初版扫描说 4 个） | **说「全是注释里的触控目标」是不准确的，已改正**。实际分三类：<br>① **真的 target 概念** —— `i18n.dart:98`（「目标：{host}:{port}」）与 `:847`（「目标：{name}（{endpoint} · pi {version}）」）**是在用的界面文案**；`conn_edit_page.dart:1` 是「『目标』配置子页面」的名字；`server_store.dart:22` 是「连接目标」的类注释<br>② **「触控目标」**（点击区）—— `chat_page.dart:1783/2237/2766`、`key_bar.dart:465`、`conn_page.dart:1168`、`files_page.dart:1030`、`main.dart:348`<br>③ **「设计目标」**（意图）—— `neu_icons.dart:218/237/240`、`chat_reducer.dart:6`<br>**结论不变**：「目标」只是同一个词在不同语境下的用法，**不是「同一功能多个入口」**。 |
| 未使用的 i18n key `ui.73e82552c8`（内容为「目标」）| 只在 `i18n.dart:331` 的定义处出现，**无任何界面引用** —— 是残留文案。本次**未清理**（属清理类改动，超出「收敛入口」的边界；`i18n_integrity_test.dart` 也未把它列为问题）|
| 「默认工作区路径」出现在 2 处 | 一处是**输入框标签**（`conn_edit_page.dart:185`），另一处是**未设置时的占位摘要**（`settings_page.dart:210` 的 `summary: ... ?? I18n.t(...)`）——不是两个编辑入口 |
| 「App 设置」在 `settings_page.dart:726/728` 两次 | 是同一分组的 `_section(...)` 与紧邻的 `if (_expanded.contains(...))`，不是两个入口 |
| `_openDir` / `_openEditor` / `_showDiff` 等被调用 2~3 次 | **全在同一文件内**（页面内部复用），不是跨页面入口 |
| `openSession()` 被调用 15 处 | 状态层方法（`server_store.dart:612`），被 UI 与内部逻辑共同调用，不是 UI 入口 |

### 刻意保留的「同一动作两种表现」

| 动作 | 两处表现 | 为什么保留 |
|---|---|---|
| **新建会话** | `chat_page._newSessionInCurrentWorkspace()`（**当前工作区**直接建）<br>`sessions_page._createSession()`（**先选工作区**再建）| 场景真的不同：会话页里是「在这个工作区再开一条」，会话列表页是「新建，工作区待定」。**不是冗余入口**。<br>但两者的错误处理文案相同（`已新建会话` / `新建会话失败`），底层调用重复 —— 可抽公共函数，属重构而非入口问题，本次未动。 |
| **复制成功提示** | `{label} 已复制`（连接信息 / 导出内容）<br>`诊断结果已复制`（诊断页）<br>`已复制`（长按消息复制）| 三处**语境不同**且措辞都恰当：诊断页说明白了复制的是什么，消息复制有明确上下文不必重复说明。**统一成一种反而会丢信息**，故保留。 |

## 四、本次收敛：「AI 配置」从「工作区」提到顶层

### 改前的问题

```
设置页 →「工作区」分组 → 展开
    ├── 「AI 配置」（模型、思考等级、技能命令、MCP 服务器）→ ConfigPage
    ├── 「文件浏览」                                          → WorkspaceFilesPage
    └── 存储占用
```

两个问题叠加：

1. **分类错误** —— 模型、思考等级、技能命令、MCP 服务器跟「工作区」没有任何关系
2. **`ConfigPage` 全 App 只有这一个入口** —— 想改模型必须**猜到**「去工作区下面找 AI 配置」。
   猜不到就以为没这个功能。

### 改后

```
设置页
├── 连接
├── 工作区      → 文件浏览 / 存储占用
├── AI 配置     → 点一下直达 ConfigPage        ← 新提到顶层，独立成行
├── 外观
├── App 设置
└── 关于
```

- **分类正确**了：AI 配置不再挂在工作区下
- **路径直了**：一次点击（原先要先展开「工作区」），少一步
- **没有重复感**：不再是「分组标题写着 AI 配置、展开后又是一行 AI 配置」

改动位置：`lib/ui/server/settings_page.dart`（从 219~256 行移出，插入到「外观」之前）
