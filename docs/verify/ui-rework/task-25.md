## 1. 审计指出的四项，逐条处理

### 1.1 语言切换器渲染内部 key（objective 点名的功能出问题）

**审计原话**：`settings_page.dart` 的语言选项引用 `lang.zh / lang.en / lang.system`，
但词表里没有这三个 key，`I18n.t` 找不到就原样返回 key，于是界面显示 `lang.zh` 这种内部串。

**核实**：属实。`grep -c "'lang\." lib/server/i18n.dart` → **0**。

**为什么被删**：这个 key 是**动态取用**的（`I18n.t(option.$2)`，key 存在列表里），
而我早期那版"清理闲置 key"的脚本只认 `I18n.t('字面量')`，判定它没有调用点就删了。
对照组：主题选择器能活下来，是因为它多一层保护 ——
`option.$2.startsWith('theme.') ? I18n.t(option.$2) : option.$2`。

**修复**：补回三条词条（语言名按惯例用其自身语言显示）：

| key | zh | en |
|---|---|---|
| `lang.zh` | 中文 | 中文 |
| `lang.en` | English | English |
| `lang.system` | 跟随系统 | System |

**证据**：`14-lang-zh.png`（中文模式下显示 `中文 / English / 跟随系统`）、
`15-lang-en.png`（已切到英文，显示 `中文 / English / System`，同屏 `App settings` 全英文）。

### 1.2 `pool_view` 显示 `{n}s`

**核实**：属实。`pool_view.dart:167` 传 `{'total': total}`，词条 `ui.c2d9323e9e` 是
`{n} 秒` / `{n}s`，占位符对不上 → 不足一分钟的时长显示成 `{n}s`。

**为什么之前的检查漏了**：我那次检查把**同一 key 在所有调用点**传的参数取了**并集**，
于是别处传对了 `n`，就把这里传错的 `total` 掩盖掉了。

**修复**：改为 `{'n': total}`；检查逻辑改为**逐调用点**比对。

### 1.3 验证工具的结构性盲区

**审计原话**：覆盖率脚本只查"中文字面量"和"定义了却没用"，对"引用了却没定义"和
"tp 参数不匹配"完全无感，却会打印 ✅。

**修复**：新增 `tool/i18n_audit.py`，**八项**检查：

| 项 | 检查内容 | 旧脚本有吗 |
|---|---|---|
| ① | 代码里仍是中文字面量 | 有 |
| ② | 定义了却没有引用 | 有 |
| ③ | **引用了却未定义**（含 `lang.zh` 这类**动态取用**的 key） | **新增** |
| ④ | **逐调用点** tp 参数不匹配（不取并集） | 改 |
| ⑤ | 英文值里含中文（英文模式会漏中文） | 新增 |
| ⑥ | 中英文占位符集合不一致 | 新增 |
| ⑦ | 中文值疑似被截断或残留 `${...}` | 新增 |
| ⑧ | **用 `t()` 调用了含占位符的词条**（该处应改用 `tp`） | 新增 |

另外，解析词条行**不再用正则**（历史上正则被值里的转义单引号 `\'` 截断过，见 2.1）。

### 1.4 服务端中文错误正文直达界面（次要）

**核实**：属实。`server/index.mjs` 的错误体是中文（例 409 的「这条会话正在运行，先停下再删」），
`server_client.dart:_explainStatus` 把 `body` 原样嵌进 toast。

**修复**：`_explainStatus` 现在对正文做**含中文检测**，含中文就丢弃、退回本地 i18n 文案：

```dart
final safe = RegExp(r'[\u4e00-\u9fa5]').hasMatch(body) ? '' : body;
if (status == 404) {
  return safe.isEmpty ? I18n.t('ui.588c5be1a0')
                      : I18n.tp('ui.07d8607b07', {'body': safe});
}
return I18n.tp('ui.a1a3b0d3e1', {
  'code': status,
  'body': safe.isEmpty ? I18n.t('ui.ee85679cef') : safe,
});
```

顺带把原来硬编码在代码里的全角冒号 `'HTTP $status：…'` 收进词条
（`ui.a1a3b0d3e1`：中文用全角、英文用半角），这样英文模式下不再是中文标点。

## 2. 用新工具揪出的另外三类问题（审计没点、但确实会显示给用户）

### 2.1 词条的中文值被截断

```
'ui.d99dc368ab': ('手机端不内嵌预览 \${ext.replaceFirst(', 'No inline preview for {ext} on mobile'),
'ui.e96f1cf9ba': ('远程 · \${parsed.host.split(', 'Remote · {host}'),
```

值以 `(` 和 `split(` 结尾就断了。根因：更早的脚本用正则 `'([^']*)'` 解析词条行，
遇到值里的转义单引号 `\'` 就截断，然后**把截断结果原样写回**。
界面在中文模式下会显示这半截串。

**修复**：手工切分（找 `': ('` 与最后一个 `', '`），两条词条按英文语义补全。
新脚本的 ⑦ 项专门守这个。

### 2.2 词表里存在双重转义

18 处值是 `\\n` / `\\$`（双反斜杠），Dart 里那是「字面反斜杠 + n」，
界面会显示 `\n` 这种字符；正确写法是单反斜杠（`\n` 换行、`\$` 字面美元符）。

**修复**：还原为单重转义；其中 `ui.2cdecccb2e` 原为三重（`\\\$`），单独再降一层。
（过程里 `ui.2cdecccb2e` 一度被写成 `\\$`，Dart 报 `Expected an identifier` —— 已修。）

### 2.3 `t()` 调用了含占位符的词条 → 界面漏出 `{n}`

**发现方式**：实机截图。设置页「后台」区块的说明显示 `上限：最多 {n} 条会话、`。

**根因**：`settings_page.dart:402` 用 `I18n.t('ui.86f594ad37')`，
而该词条是 `上限：最多 {n} 条会话、` —— `t()` 不做占位符替换。
同一个词条在 784 行有**正确写法**（`I18n.tp(... {'n': SessionCache.maxSessions})`），
而且这两条 key（`ui.86f594ad37` / `ui.c97d59e36c`）内容完全重复。

**修复**：402 行改用 `tp` + `SessionCache.maxSessions`，删除重复词条 `ui.86f594ad37`。
新增 ⑧ 项检查防止再犯。

**证据**：`16-notif-selfcheck-zh.png` —— 同屏显示 `上限：最多 5 条会话、`（已替换）
与自检信息 `lastNotified=(never sent)`（英文 key-value）。

## 4. 诚实登记

- **服务端错误正文**：现在的策略是"含中文就丢弃"。代价是英文模式（以及中文模式）
  下，服务端给的**具体**原因会退化成通用文案（如 `HTTP 409: (empty response)`）。
  更好的做法是服务端返回**结构化错误码**、由客户端映射文案，但那要改服务端协议，
  超出本轮范围，先保证不泄漏中文。
- **词条重复**：本轮删掉了 `ui.86f594ad37`，但词表里仍可能有个别同义不同 key 的条目
  （如 `ui.1f75ab9c48` 与 `ui.9d3c5fe8d6` 都是「N 分钟前」）。功能与显示都正确，
  合并需要改调用点，风险大于收益，未动。
- 本轮我在修 const 与转义时**自己引入过两次编译错误**（`DiagStep` 的 const、
  `\\$` 的非法转义），都是在 `flutter analyze` 门禁下当轮发现并修掉的，如实记录。


## 5. 审计第七轮追加：三处回归（本节对应修复）

审计指出 task-25 声称的"八项全 0"与三处**中文模式可见**的坏值矛盾，且其中两处**原本是对的**
（`task-13.md` 与 `04-settings-cache-limits.png` 里显示的就是干净的 `已缓存 2 条会话 · 共 91.0 KB`）。
经核实全部属实 —— 多出来的 `$` 是我上一轮把 Dart 插值 `${n}` 转义成 `\${n}` 之后
**没有走完替换**留下的残留。

| key | 坏值 | 应然 | 界面症状 |
|---|---|---|---|
| `ui.745a442139` | `已缓存 \${n} 条会话 · 共 {size}` | 去掉反斜杠 | `已缓存 $2 条会话 · 共 91.0 KB` |
| `ui.cb3f40c93e` | `离线 · 显示 {time} 的缓存（\${n} 条{dropped}）` | 去掉反斜杠 | `（$1 条）` |
| `ui.20f9b96cf2` | `本轮 {n} 次工具调用{files} 个文件' : ''}` | `本轮 {n} 次工具调用{files}` | 尾部漏出代码残片 |

### 我的 ⑦ 检查为什么放过了它们（这条教训最值钱）

原来是这样判定的：先把值里的 `
`、`\$`、`'` **无差别剥掉**，再看剩下有没有异常。
我这么做是为了压掉 `\$5`（字面美元符，合法写法）这类误报 ——
结果 `\${n}` 也被剥成了 `{n}`，看起来完全正常。

**用一个"宽恕"规则去压误报，把真错误一起宽恕掉了**：工具打印 ✅，界面却是坏的。
绿色门禁建立在盲区上，比没有门禁更危险 —— 它会让人相信检查过了。

**改法**：按**模式**判定，而不是先做无差别剥离。

| 模式 | 判定 |
|---|---|
| `\${`（反斜杠 + 美元 + 花括号） | **坏** —— 插值残留，应直接写 `{n}` |
| `\$` 后跟数字或普通字符（如 `\$5`） | 合法 —— 本意是要显示字面美元符 |
| 连续两个反斜杠 | **坏** —— 双重转义 |
| 值里出现 `'` | **坏** —— 代码残片 |
| 以 `(`、`[`、`,`、`.`、`split(`、`replaceFirst(` 结尾 | **坏** —— 疑似截断 |

### 验证这个检查真的有效（而不是只看它打印 0）

光看到 0 不能证明检查有用。于是**故意往词表注入一处已知坏值**再跑：

```
⑦ 中文值疑似被截断或残留插值：1 条
     ui.745a442139  '已缓存 \${n} 条会话 · 共 {size}   <- 插值残留（应直接写 {n}）
```

能抓到、并给出具体原因；还原后归零。**这才叫"检查有效"。**

## 6. 审计第八轮追加：命令面板漏出内部 key（我的第二个盲区）

**审计指出的**：`lib/server/i18n.dart` 的 `describe()` 在「中文模式 + 该命令没有中文说明」时
返回 `'$en（${t('common.untranslated')}）'`，但词表里**没有** `common.untranslated`
→ `t()` 找不到就原样返回 key → 中文模式下命令面板显示 `（common.untranslated）`
而不是 `（未翻译）`。审计还查了正在运行的服务：40 个命令里**恰好 1 个**未翻译
（`skill:playwright-cli`），所以这一支**真的可达**。

**核实**：属实。`grep -n "common.untranslated" lib/server/i18n.dart` 只有 891 行的引用，
`_strings` 里没有定义。而 `task-19-i18n.md` 第 26 行、旧截图 `task-19/c6-slash-panel-zh.png`
里显示的正是 `（未翻译）` —— 说明这条词条**曾经存在**，是在我"清理闲置 key"那次被误删的
（当时补回了 `tab.*` / `theme.*`，漏了它）。

### 盲区二：我把词表文件从扫描里排除了

```python
def dart_files():
    return [f for f in glob.glob('lib/**/*.dart', recursive=True) if norm(f) != I18N_FILE]
```

当初排除 `i18n.dart` 是为了别把**词条值**当成"漏翻文案"。
代价是：**从词表文件内部引用未定义 key，永远看不见**。
而且内部调用写的是裸 `t('key')`（不是 `I18n.t('key')`），正则也不匹配 —— 双重看不见。

这跟上一轮的毛病**性质完全相同**：为了压误报而排除一整块，把真错误一起排除了。

### 修法

1. 补回词条：`common.untranslated` = `未翻译` / `not translated`。
2. 审计脚本加 **⑨ 词表自身引用了却未定义** —— 单独扫 `i18n.dart`，
   用能匹配裸调用的正则（`(?<!\w.)t[p]?\(\s*'…'`），而非 `I18n.t(`。
3. `scan()` 里把**内部引用也计入「被引用」** —— 否则这条只被 `describe()` 用到的词条
   会被 ② 误报成"定义了却没有引用"（这是加了 ⑨ 之后立刻出现的一次误报，也因此被发现）。

### 验证 ⑨ 有效（不是只看它打印 0）

临时**删掉 `common.untranslated`** 再跑：

```
⑨ 词表自身引用了却未定义：1 个
     common.untranslated
```

能抓到；还原后归零。
