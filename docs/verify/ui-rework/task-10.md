# task-10 · 后台保活与连接可靠性（核心完成；前台服务留给任务⑪）

## 做了什么

| 机制 | 代码位置 | 解决什么 |
|---|---|---|
| 退后台记时间、回前台补同步 | `ServerStore.markPaused()` / `resumeSync()` + `main.dart` 的 `didChangeAppLifecycleState` | 回来不用手点重连；自动补连接、补会话列表、**重开会话拿一次完整快照**（后台期间推的事件收不到），并提示「已自动重连 · 离开期间新增 N 条 · 离开了 X 分钟」 |
| 记住上次会话 | `AppPrefs.lastSessionId`（`openSession` 时写入） | **进程被系统杀掉**后重开也能回到刚才那条会话 |
| 恢复后自动跳到会话页 | `main.dart` `_maybeJumpToChat` | 回来是想接着聊，不该停在连接卡上（只跳一次，用户自己切走不再拽回来） |
| 断线自动重连 | 原有的 `_scheduleReconnect()`（SSE 断开后退避重试，最多 10 次）+ `ensureConnected()` | 服务端重启/网络抖动后自己回来 |

### 过程中修掉的一个真 bug

第一次验证时「恢复上次会话」**完全没生效**。根因是竞态：`connect()` 在 `AppPrefs.load()` 完成前就读
`lastSessionId`，读到空字符串。改法：`connect()` 开头 `await AppPrefs.instance.load()`，
并把 `load()` 改成幂等（不覆盖内存里的新值）。

## Android 的现实（写清楚，不装）

- 普通 App 退到后台会被 **Doze / 冻结**：实测发出去那条消息的「已发送·撤回」提示条在后台 100 秒后**还在**
  （它的 6 秒定时器没走完）—— 说明进程被冻结过，定时器停了。
- 因此**长任务想在后台真的继续跑，必须有「前台服务」（通知栏常驻）**：那需要引入原生插件
  （`flutter_foreground_task` 之类）。我把它放在**任务⑪（通知）**里一起做，
  因为通知栏常驻进度本来就是那一条要求的一半，两件事用同一套机制。
- 本轮做到的保证是：**回来不用手连、消息自动补齐、被杀也能回到原会话**。
