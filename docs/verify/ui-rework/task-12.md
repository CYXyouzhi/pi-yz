## 这轮修掉的一个真实缺陷

| 缺陷 | 现象 | 修法 |
|---|---|---|
| 存不下第二台机器 | 连接页只能「改现有配置」——`_collect()` 的 id 取 `_editingId`，而 `_editingId` 一进页面就被填成当前那台，所以怎么改都是覆盖同一条 | 「已保存」标题行加「＋ 新增」入口：清掉 `_editingId` 并清空表单，保存时才落成新条目。合同②「可保存多台机器」的前提就是这个入口 |

## 安全边界（写清楚，别含糊）

- **token 不进广播**。发现应答里只有名称、端口、pi 版本、是否开着配对窗口 —— 广播是整个局域网都能看到的。
- **配对码才是换 token 的钥匙**：只在用户显式打开窗口后存在，默认 5 分钟，用过立刻作废（实测第二次用同一个码返回「配对窗口没开」）。
- 不想要这个窗口就 `--no-pair` 启动。
- 导出的诊断报告里 token 是掩码的（`pi********26`），可以放心发给别人。

## 复现步骤（MuMu 上自己再看一遍）

1. 电脑端：`cd pi-yz/server && node index.mjs --host 0.0.0.0`（记下终端里的配对码）。
2. App：设置 → 连接 → 「扫描局域网」→ 点列出来的那台 → 填配对码 → 配对成功后自动连上并保存。
3. 「连接诊断」看五项；「复制结果」把报告贴出来看 token 是不是掩码的。
4. 把主机地址改成 `10.1.1.199`（不存在）→ 「测试连接」，看是不是给出「找不到这台主机」而不是「连接失败」。

## 踩到的坑（留给后面几节）

- **MuMu 的 display id 每次启动 App 都不一样**（65 → 66 → 67 → 69 → 70 → 71）。手工用 `input -d 70` 发事件会全部打空，必须走 `tool/ctrl.py`（它会自己探测 App 在哪块虚拟屏上）。本轮因此白绕了几步。
- 通知栏属于主屏 display、App 在虚拟屏上，所以通知栏截图要用 `screencap -d <主屏 token>` 单独截（见 task-11）。

## 已知不足

- **没做扫码配对**（合同写的是「自动发现或扫码」二选一）。选自动发现的原因：扫码要引相机 + 二维码解析两个三方库，而发现这条链路用 `dart:io` 就能自己做，且验证成本低。要扫码的话，服务端 `connectInfo()` 里已经能生成 `pi-yz://host:port?token=...` 形式的文本，加一个二维码渲染即可。
- **发现只在同一子网内有效**。跨网段（VPN、公司大内网）还得手填地址，这一版没做跨网段发现。
- **配对窗口默认自动开 5 分钟**。方便演示，但严格来说「默认开」不如「默认关」。想关就 `--no-pair`；这台机器在局域网里的可信度用户自己判断。
