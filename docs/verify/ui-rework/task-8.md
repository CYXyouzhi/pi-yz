# task-8 · 用量可视化：速度 / 命中率 / 逐轮明细 / 上下文 / 花费 / 额度预警（已完成）

新增：`server/lib/usage.mjs`、`lib/ui/server/usage_page.dart`，接口 `GET /api/usage` 与
`GET /api/sessions/:id/usage`；会话信息面板多了「用量明细」入口。

**所有数字都从落盘 JSONL 算**（服务端扫会话文件），页面顶部就写着「数字来自落盘会话记录，不是估算」。
口径全部标在数字下面：

| 指标 | 口径（原样写在界面上） |
|---|---|
| tokens/s | 输出 tokens ÷ 各轮耗时之和；耗时为相邻落盘条目时间戳之差 |
| 缓存命中率 | 缓存读 ÷ (输入 + 缓存读) |
| 成本 | pi 记的价（`usage.cost.total`），不是我们按价目表算的 |
| 上下文 | 已用 / 窗口上限，来自 pi 的会话统计 |

## 逐项

| 项 | 做法 | 证据 |
|---|---|---|
| ① 运行中速度 | 运行期间每 3 秒调一次 `/api/sessions/:id/usage`，按落盘时间戳重算本轮速度，显示在会话页标题行（`本轮 X tok/s · Ns`） | 公式与数字在用量页可见（`u3/u4`）；**诚实的缺口**：标题行那条芯片的实机截图没抓到（两次都在截图前跑完/切到了别的会话），所以这一条的运行时界面未截图，只有代码与同口径的服务端数字 |
| ② 缓存命中率 | 面板与明细页都显示，并标注口径 | `u3-usage-page.png`（本次会话 缓存命中率 0.0% + 口径行） |
| ③ 逐轮明细 | `/usage` 返回每轮：输入/输出/缓存读/缓存写/思考/成本/耗时/速度/命中率/结束原因，页面逐轮一张卡 | `u4`（平均生成速度 + 今天本月）、明细卡片在页面下方 |
| ④ 上下文进度条 | 进度条 + **70% 变黄 / 85% 变红**，并写清「自动压缩开启时到阈值会自己压一次 / 关了就手动 /compact」 | `u3-usage-page.png`（1.9% 绿色 + 阈值说明） |
| ⑤ 花费看板 | 本次会话 / 今天 / 本月（今天与本月来自跨会话聚合） | `u4`（今天 431.23M · $9.275，本月 1335.59M · $27.772，统计范围 244 条会话） |
| ⑥ 额度预警 | 按本机当天花费分级（≥$5 黄、≥$10 红），**明写「这是按本机落盘用量的估算，不是服务商官方额度」**，并指向无人值守那项 | `u4` 下方「额度预警」段 |
| ⑦ 与落盘对账 | 见下面的对账记录 | 一致 |
| ⑧ 数据缺失显示「—」 | 所有可空字段（缓存读/写、思考、耗时、速度、命中率、成本）拿不到就显示 `—`，不用 0 冒充 | 代码：`_tokens(null) => '—'`、各 `_row` 的空值分支 |
