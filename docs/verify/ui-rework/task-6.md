## ③ 多行输入 / 发送 / 换行

现状与理由（这一条本来就有，本任务只是确认并写清）：

| 行为 | 怎么做的 |
|---|---|
| 软键盘回车 | **换行**（`TextInputAction.newline` + `maxLines: 5`）—— 手机上误触回车就发出去很痛苦 |
| 明确发送 | 输入框右侧的发送键 / 按键条里的 `⏎ 发送`（任务④加的） |
| 长文本 | 输入框随内容长到 5 行，再多就内部滚动 |
| 发送失败 | 文字**放回**输入框并提示原因（以前失败会把内容吞掉） |

`task-4/08-enter-sent.png` 是 ⏎ 发送的实测；多行输入在本次测试里出现过（消息带换行时输入框撑到两行）。

## ④ 素材直传：相册 / 文件 / 剪贴板

`＋` → 素材三项：

| 入口 | 行为 | 证据 |
|---|---|---|
| 相册 / 图片 | 系统相册选图 → 读成 base64 挂在消息上（输入框上方出现缩略 chip，点一下移除）→ 发送时随 `prompt.images` 一起给 pi | `04-image-attached.png`（chip）；落盘证据见下 |
| 文件 | 选文件 → 传进当前工作区 → 把**绝对路径**写进输入框（pi 按路径读文件） | 代码路径 + `store.lastUploadedPath` |
| 粘贴剪贴板 | 读剪贴板**文本**插进输入框 | 代码路径 |

**图片真的到了 pi（落盘为证）**：会话 JSONL 里那条用户消息的内容块是

```
内容块: ['text', 'image'] | mimeType: image/png | base64 长度: 1444244
```

**相机（拍照）没做** —— 诚实说明原因：Flutter 读相机需要再加一个原生依赖（`image_picker`），
当前工程只有 `file_picker`（相册/文件走的是系统选择器，够用）。
按合同「做不了要写明原因」这一条记在这里；要补的话就是加依赖 + 申请 CAMERA 权限两件事。

**剪贴板图片也没做** —— Android 读图片剪贴板需要额外原生能力，Flutter 自带 `Clipboard` 只有文本；
实际使用上「相册选图」与「粘贴图片」效果等价，所以先不引依赖。

## ⑤ 误发保护：发送后可撤回

**做法**：发送成功后，输入框上方出现一条**横跨整行的「✓ 已发送 … 撤回 ✕」**，6 秒内点它就：
中断刚起的那一轮（`abort`）+ 把文字放回输入框。

**为什么不用 toast 里的行动按钮**：一开始用的是 `NeuToast(actionLabel: '撤回')`，
设备实测**那个 action 点不到**（`SnackBarAction` 的命中区与手势/自动化坐标对不上，
连续两次点空、运行也没停）。误发保护必须真的能点到，所以改成输入框上方的一整条按钮。

**诚实边界**：撤回**不会**把已经写进会话历史的那条删掉（真要回退得走分支树 / 编辑重发，
那是任务⑨的事），所以提示语写的是「已撤回：已中断本轮，文字已放回输入框（那条仍在历史里）」。

**证据**：`05-undo-bar.png`（撤回条出现，本轮的思考/工具调用正在进行）
→ `06-undone-text-back.png`（点完之后：输入框里是 `undo-bar-2`，运行已停）。
