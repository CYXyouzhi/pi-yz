## 先说清楚一个设计决定（很重要，不然会以为是没做完）

`key_bar.dart`（541 行）是**终端时代**写的：`onKey` 回传的是 `KeyEncoder` 编好的**终端转义字节**
（Ctrl+A → 0x01、方向键 → CSI 序列…）。

但我们现在的通道是 **pi（一个 agent）而不是终端**：服务端 RPC 只有 `prompt / steer / abort / …`，
**没有任何「把原始按键喂进去」的接口**。所以：

> 按键条发来的序列，在 App 侧被**翻译成 pi 真实存在的动作**，绝不原样发给会话。

这样每个键都有真实效果，而不是发一堆 agent 看不懂的字节。映射表：

| 键 | pi 侧动作 |
|---|---|
| Esc | 三级退让：先收起命令/文件面板 → 再中断正在跑的任务 → 最后清空输入 |
| Tab | 补全：把当前匹配的第一条命令 / 文件填进输入框（首页命令面板同源数据） |
| ⏎ | 发送（手机软键盘回车默认是换行，所以需要一个明确的发送键） |
| ^C | 中断当前任务（`abort`） |
| ↑ / ↓ | 翻自己发过的消息历史（本次会话内存里，最新 50 条） |
| ← / → | 光标左右移一格 |
| Home / End | 光标到开头 / 末尾 |
| PgUp / PgDn | 消息列表按一屏上下翻 |
| / 命令 | 打开斜杠命令面板 |

## ① 按键在输入栏可见可点，且都有真实效果

**入口改了**：输入框左侧的 ⌘ 按钮以前是「打开命令面板」，现在按用户的原话——
「那个按钮本来应该是用来加载手机上无法输出的键盘按键的」——改成**调出按键条**；
命令面板挪到按键条里的「/ 命令」键（手打 `/` 也一样出）。

**证据（逐个键实测）**：

| 键 | 截图 | 看到什么 |
|---|---|---|
| 折叠态整条 | `01-collapsed-bar.png` | 输入框上方一条：Esc / Tab / ↑ / ↓ / ▤全部 / / |
| 展开态 + 中文标注 | `02-expanded-panel-cn-labels.png` | Esc 退出 · Tab 补全 · ⏎ 发送 · ^C 中断 · ↑上 ↓下 ←左 →右 · PgUp 上页 PgDn 下页 Home 开头 End 末尾 |
| Tab | `03-tab-complete.png` | 输入 `/` 再按 Tab → 输入框变成 `/skill:edge-tts`，面板收起 |
| ↑ | `04-up-history.png` | 输入框回到刚发过的 `kb-history-test` |
| PgUp | `05-pageup-scroll.png` | 消息列表向上翻了一屏（与原视图相比内容不同） |
| ^C | `07-ctrl-c-abort.png` | 工具卡从「bash sleep 40 · 运行中」变成「bash · Command aborted · 失败」，发送键复位 |
| ⏎ | `08-enter-sent.png` | 输入清空、消息发出，pi 已回话 |
| Esc | `09-esc-cleared-input.png` | 输入框被清空（回到占位文字） |

**关于「确实发送到会话」**：Enter 与「Tab 补全后再发」走的是同一条 `sendPrompt` 通道，
会话 JSONL 里能看到对应输入（如 `user | run bash sleep 40 then reply done`）；
Esc / ^C 的效果是 pi 侧的 abort（工具卡显示 `Command aborted` 即服务端真实状态）。
其余键（Tab / ↑↓ / ←→ / Home / End / PgUp / PgDn）是**界面动作**，
它们不该也不需要在会话里留痕 —— 这一点如实说明，不硬套「都发到会话」。

## ② 可收起 / 展开，且不遮挡输入框与消息

按键条是**参与布局**的（放在消息列表与输入框之间的 Column 里），不是浮层：
展开后消息列表自动上移，输入框与消息都不被盖住。截图 `01`（折叠）与 `02`（展开）可直接对比。

## ③ 快捷键含义有中文说明

键帽下面就是中文：退出 / 补全 / 发送 / 中断 / 上 / 下 / 左 / 右 / 上页 / 下页 / 开头 / 末尾 / 命令，
标题行还有一行提示：**「Esc 收起面板/中断 · Tab 补全 · ↑↓ 历史」**。

另外把 **Ctrl / Alt / ⇧ 修饰键那一行隐藏了**（`showModifiers: false`）：
聊天通道里除 Ctrl+C 外没有修饰键语义，摆一排按了没反应的键等于骗人。
终端场景若以后真的需要，传 `showModifiers: true` 即可恢复。

## ④ 与「插话 / 排队消息条」不冲突

任务在跑的时候（`06-running-steer-notice.png`）：输入框占位文字是「运行中…可输入以插话」、
发送键变成 ✕（中断），**按键条仍然完整可用** —— 同一张截图里还能看到 `^C 中断` 键，
点它就是 `07` 的效果：任务被中断。两者互不抢位置、互不吞事件。

## 附带修掉的一个死入口（不在原计划里，但必须修）

验证 ⏎ 时发现：**空态（没打开任何会话）下输入文字点发送，什么也不会发生**。
根因：`ServerStore.runCommand` 在 `currentSessionId == null` 时直接返回 `null`，
而 `sendPrompt` 只把 `null` 当成失败 → 用户看到「打完字点发送没反应」。

**改法**：`sendPrompt` 在没会话时先按默认工作区自动开一条会话再发（工作区为空则明确提示去设置里填）。
实测：空态输入 `kb-history-test` 直接发送成功，pi 正常回话并反问澄清问题。

（这条也顺带证明了扩展对话框在 App 里能正常渲染并回传答案。）
