## 1. 折叠态美观化

**改前**（用户截图）：设置页收起后是「纯文字 + 右箭头」，无卡片、无图标，
区块间大片空白 —— 像没做完。

**改后**：每张卡片 = 图标 + 标题 + 一行摘要 + 箭头。

摘要那一行不是装饰：它让**收起时仍然看得到状态**（`已连接 · 10.1.1.195:30142`、
`C:\Users\...\123`、`pi 1.0.0`）。否则收起就等于把信息藏起来，而不是整理。

**展开态**：普通标题行 + 内容卡片 —— 标题不再带卡片底色，避免「两张卡片叠着」。

新增公共组件 `lib/ui/neu_section.dart`，三处折叠统一到这一套
（原先 settings_page 一套 `_collapsed`、sessions_page 一套 `expandedWorkspaces`、
usage_page 干脆没有，默认状态还不一样 —— 这正是用户说的
「有的地方点了会收、有的地方点了没反应」的来源）。

**截图**：`p1-settings-collapsed-cards.png`（收起）、`p2-settings-conn-expanded.png`（展开）。

## 4. AI 配置页 —— 顺带查出两个 bug

`p4-ai-config-collapsed.png`（**本轮重拍**）：6 个分组（模型 / 思考等级 /
Provider 凭据 / 技能与命令 / pi 插件（10） / MCP 服务器），每张卡片带图标，

> **上一版这张图是错的**：审计指出它其实是**设置页**的截图（顶部 120px 与
> `p2-settings-conn-expanded.png` 逐像素相同），而 AI 配置页的标题是「AI 配置」。
> 指控成立 —— 那次拍的确实不是这个页面。本轮从「设置 → 工作区 → AI 配置」
> 真走了一遍并重拍。

展开验证分类（objective 点名的「技能/命令、插件/MCP」）：

| 文件 | 展开的是 | 看到什么 |
|---|---|---|
| `p4b-ai-config-skills-expanded.png` | 技能与命令 | 技能（27）/ 扩展命令（32）/ 内置命令（13）|
| `p4c-ai-config-plugins-expanded.png` | pi 插件（10）| 10 个包，各自带安装路径与「电脑端已汉化 N 处文案」|

**查出并修掉的 bug ①**：我早前那个「补折叠判断」的补丁脚本，把
`if (_expanded...) ...[` 插到了 `_section(...)` **之前** —— 于是**标题也被包在
折叠里**，收起时**连分组标题都不显示**。这正是「全收起后整页只剩标题」的真因，
我当时**错误归因**成「设计问题」，还因此破例把「模型」组默认展开（那个破例又被
审计指出违背「一律默认收起」）。现在 `if` 移到 `_section` 之后（6 处），
分组全部默认收起。

**查出并修掉的 bug ②（本轮新发现）**：「pi 插件（10）」点开是**空的**。
`_section` 用**标题**当展开键，而插件组标题里带计数（`（10）`）；内容判定却
写死 `_expanded.contains('plugins')` —— 两边永远对不上，所以箭头会翻转、
内容一个都不显示。修法：`_section` 增加 `stateKey` 参数，插件组显式传
`stateKey: 'plugins'`（标题里的计数变化也不会再丢展开状态）。

## 7. 开始页 ② 活跃会话可手动关闭 —— **UI 前后截图已取得**

**改了什么**：服务端新增 `DELETE /api/pool/:id`（只移出池、**不删文件** ——
与 `DELETE /api/sessions/:id` 的破坏性语义分开，用户说的是「不跑了别再显示」，
不是「把记录删掉」）。App 侧在活跃会话那行加了 `×` 按钮。

**服务端侧证据**（可复现）：

```
[server] 已关闭活跃会话 01a10b83-...（文件保留）
GET /api/pool  ->  池里会话数: 1     （关闭前是 2）
```

**查出并修掉的一个真 bug**（这一条是实打实的）：修好之前，点 `×` 后
**界面不刷新** —— 服务端已经归零，界面仍显示「共 1 个会话活着」，
**切到别的 Tab 再切回来才正常**。根因：列表页用 `ValueListenableBuilder`
**只监听 `_store.sessionsRevision`**（它自己的注释写了理由：流式时 notify 每秒
几十次，244 条列表跟着重建纯属浪费），而 `pool` 的变化不在那个信号里。
修法：`loadPool()` / `closeLiveSession()` 在 pool 真的变化时 `_bumpSessions()`。
修完后实测：点 `×` 后 2 秒（未切 Tab）服务端池 1→0、界面区块消失。

**UI 侧的前后截图已经补齐**（两张都是本轮在 MuMu 上实拍）：

| 文件 | 内容 |
|---|---|
| `p5b-pool-close-before.png` | 开始页，「共 **2** 个会话活着」，第一条右侧就是 `×` |
| `p5c-pool-close-after.png` | 点完 `×` → 「共 **1** 个会话活着」，**没有切 Tab** |

服务端 `/api/pool` 同步从 2 条变 1 条。上一版 `p5b` 之所以不含活跃会话，
根因是我**造不出活跃会话** —— 当时只想着从 UI 点「新会话」，而它受
「是否已有空会话 / 是否有默认工作区 / token」等条件限制；这次改用
`POST /api/sessions {cwd}` 造池内会话，UI 三秒轮询就把它显示出来了。
**`×` 是回到 App 里真点的**（不是靠接口关的），这才算验证了 UI。

## 10. 附：修掉用户报的「快捷键面板空白」

**现象**（用户提供截图 `屏幕截图 2026-10-05 190129.png`）：会话页点 `⌘` 调出按键条
后再点 `▤` 展开，面板里**只有「快捷键」三个字**，12 个键位一个都不显示。
我在 MuMu 上如实复现了同一个画面（`p10-keybar-expanded-broken.png` 与用户截图一致）。

**根因**：不是没画出来，是**布局中途断言失败**。
`_KeyCap` 内部那个 `Row` 用了 `Flexible(label)`；而展开面板标题行里的 `/` 和
「完成」是外层 `Row` 的**非 flex 子项**，Flutter 给非 flex 子项的主轴约束是
**无界**的（`RenderFlex._constraintsForNonFlexChild` 水平方向只写 `maxHeight`，
`maxWidth` 缺省即 infinity）——「有 flex 却无界」直接抛出：

```
RenderFlex children have non-zero flex but incoming width constraints are unbounded.
  #4 RenderFlex._computeSizes        (flex.dart:1237)
  #3 RenderAnimatedSize._layoutStable(animated_size.dart:329)
```

布局中断后整块面板只剩标题；设备日志里还能看到连锁的
`RenderBox was not laid out ... Failed assertion: 'hasSize'`。

**为什么原来 132 个测试没抓住**：`widget_test.dart` 的 `_KeyBarHarness` 用
`Align(bottomCenter)` 包 `NeuKeyBar`，而聊天页里它是父 `Column` 的**直接子项**；
两者宽度约束不同，而这个 bug 只在后者出现。

**修法**：`_KeyCap` 按约束是否有界二选一 —— 有界用 `Flexible(flex: 1)`
（标号必须能收缩，否则实测溢出 6.1 逻辑像素），无界用 `flex: 0`
（退化成非 flex 子项，避开断言）。

**证据**：

| 文件 | 说明 |
|---|---|
| `p10-keybar-expanded-broken.png` | 修复前，MuMu 实测复现（与用户截图同画面）|
| `p11-keybar-expanded-fixed.png` | 修复后，标题行 + 12 个键位都在 |

**回归测试**：`test/key_bar_layout_test.dart`（折叠态 / 展开态 / 来回切换 3 条），
按聊天页的真实层级搭，不再用 `Align` 包。

**门禁**：`flutter analyze` 无问题；`flutter test` 135 全过（原 132 + 新 3）。
