# 快捷键栏的 `Esc` / `Tab` 溢出（用户发现，非本轮目标范围内）

## 1. 现象

会话页点输入区的 `⌘` 按钮弹出快捷键栏后，debug 构建下出现两条警告：

```
Esc OVERFLOWED BY 4.8 PIXELS
Tab OVERFLOWED BY 4.8 PIXELS
```

Flutter 的 debug 溢出指示是**黄黑斜条纹 + 红字**，直接盖在界面上（见图 `f1`）。
更要紧的是：这不只是警告 —— **`Esc` / `Tab` 的文字确实被裁掉了**（见并排对比 `f4` 上半张，
`Esc` 右边缺了一点）。release 构建不显示警告，但裁切照样发生。

## 2. 我是怎么漏掉它的（先认这个）

我本轮只验证了**导航栏四态**（收起/展开/点 Tab 收起/下滑收起），**没有把会话页的其他可点控件走一遍**。
`⌘` 按钮就是没走到的那一个。用户问了「你测试了吗」—— 答：这个没测。

补测的方法是：逐个点会话页的可点控件（`＋`、`⌘`、`🚀`、标题栏三个按钮），每点一次截图比对 md5。
`＋` 正常、`🚀` 正常、`⌘` 弹出正常但**带着这两条警告**。

## 3. 根因（数字与 Flutter 报的一致）

折叠态按键栏有 6 个键，`_MiniRow` 里用 6 个 `Expanded` **等分**宽度：

```
按键栏内宽（NeuInset）≈ 342 逻辑
每格 = (342 − 8) / 6 = 55.7
_KeyCap 内：减 Padding(all: 5)×2、减键帽外 padding(水平 4)×2
  → Row 只剩 37.7 可用
而 "Esc"/"Tab" 的键帽需要 ≈ 42.5
  （3 字符 monospace 10.5 + 键帽自身水平 padding 12）
→ 超出 4.8        ← 与 Flutter 报的 4.8 PIXELS 完全吻合
```

**为什么没人能把它压回去**：`Row` 里只有 `label`（「退出」「制表」那类说明字）包了 `Flexible`，
**键帽自己是固定宽度的 `AnimatedContainer`** —— 内容比格子宽时，它不会缩，只能溢出。

## 4. 为什么这不是本轮改动引入的

这一条必须给证据，否则「顺手修的 bug」很容易被当成「自己捅的篓子」：

**证据一：装改前的 APK 对比。** `build/app/outputs/flutter-apk/app-release.apk` 构建于
`08:39:54`，而本轮的代码改动始于 `09:4x` —— 所以它是改前产物。它的输入区还带着
**我在本轮删掉的 `⌄` 按钮**、底部**没有把手**（图 `f3` 可佐证），确实是改前版本。

拿它跑同一个测量：

| | 按键栏宽度 |
|---|---|
| 改前（release, 08:39） | 341.3 逻辑 |
| 改后（debug, 10:12） | 342.0 逻辑 |
| 差 | **0.7 逻辑**（测量噪声级） |

**证据二：代码结构。** `NeuKeyBar` 是 `chat_page.dart` 里独立的容器（输入框**上方**、参与布局），
宽度由它自己的 `Padding(fromLTRB(18,0,18,…))` 决定，**不由输入框宽度决定**。我删掉 `⌄`
按钮让的是输入框里的 `Expanded`（TextField）更宽，跟按键栏无关。

结论：**改前就有的历史 bug**。release 构建不显示溢出警告，4.8 像素的裁切在 10.5 号字上也不显眼，
所以一直没被发现。

## 5. 修法（两层保险）

改 `lib/ui/key_bar.dart`：

**① 宽度按内容分配，不再等分。**

```dart
// 改前：6 个 Expanded（默认 flex 1）等分
Expanded(child: _KeyCap(kbd: 'Esc', …))
Expanded(child: _KeyCap(kbd: 'Tab', …))
…

// 改后：Esc/Tab 是 3 个字符，其余是 1 个字符或图标
Expanded(flex: 4, child: _KeyCap(kbd: 'Esc', …))
Expanded(flex: 4, child: _KeyCap(kbd: 'Tab', …))
Expanded(flex: 3, child: _KeyCap(kbd: '↑', …))
…（↓ ▤ / 均为 3）
```

总 flex = 20，Esc/Tab 格从 55.7 → **66.8 逻辑**，`Row` 可用 48.8 > 需求 42.5，**余量 6 逻辑**。

**② 键帽包一层 `FittedBox(fit: BoxFit.scaleDown)` 兜底。**

万一某台设备的 monospace 度量比模拟器更宽，也只是把那个键帽**等比缩小**，
不会再出现溢出警告。不超宽时它完全不改变尺寸（所以展开态的大格子不受影响）。

两层是互补的：① 给足空间（正常情况不会触发缩放），② 保证任何字体度量下都不溢出。

## 6. 修复验证

| | 结果 |
|---|---|
| debug 构建点 `⌘` | **黄黑条纹与 OVERFLOWED 红字都消失**，六个键完整显示（`f2`） |
| `Esc` / `Tab` 文字 | 完整，不再被裁（`f4` 下半张是修复后） |
| `flutter analyze` | No issues found |
| `flutter test` | **121 全过**（快捷键栏原有 5 个用例均未受影响） |

复现：

```bash
flutter build apk --debug
# 装到设备后进会话页，点输入区的 ⌘
python tool/ctrl.py tap 220 1710
python tool/ctrl.py shot out.png
```

## 7. 这次修复暴露的流程问题

我的验证清单里只有「导航栏四态」和「门禁」，**没有「把会话页所有可点控件点一遍」**这一项。
而 Flutter 的溢出警告、异常弹窗这类问题**只在真的点到那个控件时才会出现**，
静态检查（analyze）和既有测试都覆盖不到。

**改进**：以后改动涉及某个页面时，除契约要求的场景外，再补一轮**该页面所有可点控件的点击 + 截图比对**
（点一次截一张，md5 不变或状态异常即为可疑）。这轮补测就靠这个方法找到了本问题。
