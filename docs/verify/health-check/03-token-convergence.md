# 03 · UI 一致性（task-4）：硬编码视觉数值收敛到设计令牌

**约束**：合同要求「不得改变现有视觉观感」。所以做法**不是**把散值硬套到现有令牌上
（那会把 11 变成 11.5、14 变成 14.5，观感就变了），而是
**先统计实际用值 → 给高频值命名（值不变）→ 再替换**。这也与 `design_tokens.dart`
里 task-21 那轮的做法一致（那次收敛了 12.5 / 11.5 / 12 / 13 / 13.5）。

## 三、豁免清单（9 处，逐条说明为什么**不**收敛）

| 位置 | 值 | 为什么不收敛 |
|---|---|---|
| `pool_view.dart:331` | `fontSize: 24` | 多会话总览里的**大号计数数字**，全工程仅此一处，属一次性排版特例；给它起名只会增加噪音 |
| `usage_page.dart:118` | `fontSize: 20` | 用量页顶部的**统计大数字**，同样仅此一处 |
| `key_bar.dart:484` | `circular(7)` | 键帽的专属圆角，与键帽尺寸耦合；键帽是一套独立的小系统（同文件已有 `keyBarH` 之类的专属令牌），单独给它一个 `NeuRadii` 会误导「通用圆角」的语义 |
| `chat_page.dart:1325` | `circular(6)` | 头部地址胶囊的小圆角，与胶囊高度（由 padding + 10.5 字号决定）耦合，属该组件的局部常量 |
| `chat_page.dart:2749` | `circular(18)` | 某个卡片的专用圆角，介于 `sm`(14) 与 `md`(20) 之间，仅此一处 |
| `usage_page.dart:136` | `circular(4)` | 进度条端点微圆角 |
| `usage_page.dart:394` | `circular(3)` | 同上，另一处进度条 |
| `main.dart:497` | `Color(0xFFE1FBF4)` | 启动闪屏（splash）的底色，是**一次性品牌色**，不属于「主题色板」（主题色在 `NeuTokens` 里按明暗两套管理，硬塞进去会破坏那套结构） |
| `neu_icons.dart:248` | `Color(0xFF000000)` | 图标系统构建 `IconData` 时需要的**基色占位**（图标最终颜色由调用处传入），不是视觉色值 |

**判断标准**：能说出「它在色板/字阶里属于哪一档」的，收敛；
只能说「这个组件就需要这个值」的，豁免并写明原因。

## 四、复现命令

```bash
# 收敛后应为：fontSize 2、radius 5、color 2
python - <<'PY'
import re, glob
from pathlib import Path
BS = chr(92)
for k, pat in [('fontSize', r'fontSize:\s*([0-9.]+)'),
               ('radius', r'BorderRadius\.circular\(([0-9.]+)\)'),
               ('color', r'Color\(0x[0-9A-Fa-f]+\)')]:
    n = sum(len(re.findall(pat, Path(f).read_text(encoding='utf-8')))
            for f in glob.glob('lib/**/*.dart', recursive=True)
            if '/theme/' not in f.replace(BS, '/'))
    print(k, n)
PY
```

## 五、第二轮补充：间距令牌（审计指出第一轮整项缺失）

**审计意见成立**：目标明确写了「硬编码的**字号/间距/圆角/颜色**」四项，
而第一轮只做了字号、圆角、颜色 —— **间距整项被跳过**，
且我在总结里写了「把所有硬编码视觉数值收敛」，与实际不符。此处补做并订正陈述。

### 5.1 收敛前后计数

| 项 | 收敛前 | 收敛后 | 收敛数 |
|---|---|---|---|
| `EdgeInsets.*` 里的硬编码数值 | 602 | **29** | 573 |
| `SizedBox(width/height: 数字)` | 334 | **0** | 334 |
| 新增 `NeuSpace` 令牌引用 | 0 | **961** | — |
| **硬编码合计** | **936** | **29** | **907** |

### 5.2 新增的 `NeuSpace` 令牌（18 档，值与原字面量相同）

命名**直接用数值**（`n8` = 8），而不是 `xs/sm/md/lg` ——
十几个档位用相对命名会「记不住哪个大」，用数值没有歧义。

覆盖 0–24 的整数即可打包掉绝大多数（统计见令牌注释）。

### 5.3 剩余 29 个的豁免清单

| 值 | 出现 | 为什么不收敛 |
|---|---|---|
| `0` | 11 | **语义是「无边距」**，框架有 `EdgeInsets.zero`；塞进 `NeuSpace.n0` 会让「间距档位」这个概念变模糊 |
| `40`/`28`/`32`/`30` | 4/4/2/2 | 出现在**组件专属尺寸**位置（键帽、卡片固定宽高），不是布局间距——它们是「这个组件要多大」，不是「两件事之间留多少」 |
| `104`/`96` | 2/1 | 同上，属固定尺寸 |
| `22`/`15`/`38` | 各 1 | 一次性特例值，出现次数不足以形成档位 |

**判断标准**（与第四节一致）：能说出「它在间距阶梯里属于哪一档」的收敛；
只能说「这个组件就需要这个数」的豁免并写明原因。
