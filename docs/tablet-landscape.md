# 平板与横屏适配

## 结论

| 形态 | 布局溢出 | 视觉 |
|---|---|---|
| 手机竖屏 360×640 | 无 | 正常 |
| 手机横屏 640×360 | 无 | 正常 |
| 平板竖屏 800×1280 | 无 | 正常（800 < 840 阈值，不触发收窄） |
| 平板横屏 1280×800 | 无 | **已修**：原来卡片被拉成三倍宽，现在收窄居中 |
| 小平板横屏 1024×768 | 无 | 同上（已收窄） |

## 发现并修掉的问题

**宽屏下内容被拉伸。** 布局是按手机竖屏（360~450dp）设计的。放到 1280dp 的
平板横屏上，卡片会被拉到三倍宽 —— 不溢出、也点得到，但读一行要横扫整屏。

这是「**不溢出 ≠ 好看**」的典型：所有断言式测试全绿，是看 golden 基线才发现的。

### 修法：一个外壳层的宽度约束

新增 `lib/ui/adaptive_body.dart`，接在 App 外壳的内容区（`main.dart` 的
`IndexedStack` 外面）一处 —— 三个 Tab 同时生效，页面自己不用知道屏幕多宽。

```
宽 ≤ 840dp  →  原样返回（手机一行都不改）
宽 >  840dp  →  左右加内边距，内容收窄到 840dp 居中
```

两个实现细节：

- **用 `Padding` 而不是 `Center` / `Align`**：后两者会给 child 松约束，页面高度
  会塌成「尽可能小」，滚动区与底部对齐都会乱。加左右内边距能让 child 拿到
  「宽度正好 840、高度照旧」的紧约束。
- **阈值 840dp**：Material 3 里「中等窗口」的上界。再宽就该上分栏布局了 ——
  那是另一件事，这一步不做。

### 这个修改是「零影响窄屏」的，而且可验证

接入后跑 golden：

| 档 | 结果 | 说明 |
|---|---|---|
| 手机 360 / 400 / 450dp | **全绿** | 窄屏一行没改 |
| 平板竖屏 800×1280 | **绿** | 800 < 840，不触发约束 |
| 平板横屏 1280×800 | 44% 像素差异 | 1280 > 840，收窄生效 → 更新基线 |

若哪天手机档的基线也变了，说明这个组件的手伸得太长 —— 那就是回归。

## 为什么用 widget 测试，而不是在模拟器上截图

MuMu 的 framebuffer 是**固定物理尺寸**：`wm size 1920x1080` 确实生效了
（`wm size` 会显示 `Override size: 1920x1080`），但 `screencap` 出来的图仍然是
1080×1920 —— 它没法真的模拟平板/横屏。MuMuManager 的 `simulation` 只能改
`android_id` / `mac_address` 这类设备标识，也改不了分辨率。

而 widget 测试换个尺寸只是一行赋值（`setPhoneSurface(tester, width:, height:)`），
还能把「不许溢出」变成**可重复的断言**：以后每次改 UI 都会重新验证一遍。
人工截图只在那一刻有效。

真机（MuMu / Android 15）仍然跑了一遍手机竖屏作为补充证据：界面正常、无异常。

## 测试怎么写的

`test/tablet_landscape_test.dart` —— 5 种形态 × 3 组场景 = 13 个用例：

1. **启动 + 遍历各 Tab**：溢出会被 Flutter 报成异常，`takeException()` 拿得到，
   所以「没有异常」= 没溢出
2. **设置页展开分组**（最长页面，最可能爆）
3. **横屏专项：底部 Tab 完整落在屏内** —— 因为**不溢出 ≠ 看得见**，
   元素可能被挤到屏幕外

与 `resolution_test.dart` 的分工：那个管**手机宽度**（360/400/450）与安全区
（刘海、手势条）、点击区尺寸；这里管**高度与形态**（横屏、平板）。

### 踩到的坑：ListView 懒加载

横屏 640×360 下，设置页下方的分组**压根还没进 widget 树**（高度小，`ListView`
只构建可见项），`find.text('工作区')` 直接报 `Bad state: No element`。
这是懒加载的正常行为，不是布局问题 —— 所以 `ui_harness.dart` 的 `openSection`
先滚到元素出现再点。滚完还找不到，那才是真问题。

## 还没覆盖的（如实列出）

这批只测了「启动 + 切 Tab + 设置页分组 + 底部导航位置」。以下需要**连接态**
或更多交互，尚未覆盖：

| 未覆盖 | 为什么 |
|---|---|
| 聊天页（消息气泡、工具卡片、输入区） | 需要连上服务端并有会话 |
| 连接页的编辑表单 | 需要进入二级页面并聚焦输入框（键盘会再挤掉一半高度） |
| 各种弹层（模型选择、目录选择、命令面板斜杠面板） | 需要连接态 + 交互 |
| 竖屏 / 横屏**切换过程**（配置变化时的重建） | widget 测试里没有真实的旋转事件 |

补的话，先在 `test/` 里造一个「已连接的假服务端 + 一个会话」的脚手架
（`server_store_test.dart` 里已有现成的假服务端写法），再按同样的形态表遍历。
